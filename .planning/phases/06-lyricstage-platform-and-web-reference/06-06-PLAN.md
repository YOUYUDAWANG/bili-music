# Phase 06-06 — Stage-first Now Playing 与演出导演 Skill · 实施计划

## 目标

把当前“全屏歌词 Canvas”升级为完整的 Apple Music 式 Now Playing + LyricStage 演出舞台，并让独立 Director 通过版本化 Skill、typed primitives 和证据合同选择或组合演出；不削弱本地 fallback、宿主时钟、逐字真相或 section 边界接管。

## Task 0 · 基线与所有权门 ✅

- [x] 保存当前本地/AI handoff、逐字、seek、pause、换歌、GPU fallback 的窄测试基线。
- [x] 明确当前 YTM snapshot 是否提供稳定封面 URL、播放/暂停、上一首、下一首与 seek；不支持项从 UI 删除。
- [x] 为 cover/current track、glyph owner、active recipe、renderer generation 建立单一 identity。
- [x] 加入静态门：全屏不得出现顶部/底部浮动 chrome、debug label、假的媒体控制。

退出门：不改视觉时既有本地/AI 路径仍通过；Bridge 能力清单有真实 DOM/Chrome 证据。

## Task 1 · 稳定 Now Playing 外壳 ✅

- [x] 新建 Stage shell：28–32% 封面列、68–72% 歌词舞台、封面色板环境。
- [x] 显示真实封面、标题、艺人、常驻细进度和 Bridge 真正支持的运输控制。
- [x] 删除现有角标、顶部/底部控件、等待文案和 audience debug。
- [x] 封面缺失/加载失败使用确定性本地占位；换歌拒绝旧封面回写。
- [x] 720p、1080p、1440p、16:10 与窄窗口分别做布局门。

退出门：第一眼是完整 Now Playing；无操作 chrome 不遮歌词；换歌/seek/断连不出现旧封面或错误控制状态。

## Task 2 · AMLL 技术 spike 与许可证门 ✅

- [x] 比较“AMLL normal + LyricStage hero”与“AMLL 算法 + 单 renderer”两条路径。
- [x] 对 word timing、line-only、长 CJK、拉丁混排、duet、random seek、resize 做同一 fixture A/B。
- [x] 验证 glyph owner 唯一、无双层残影、无 section handoff 跳字、无每帧 React 更新。
- [x] 明确 AGPL-3.0 许可证、NOTICE、修改声明与对应源代码提供流程。
- [x] 形成 `06-06-AMLL-ADR.md`，选择算法原则 + 单 renderer。

退出门：AMLL 接入边界可执行且法律/技术义务明确，不以“像 Apple”作为唯一选择理由。

## Task 3 · Motion Bible 与本地 Effect Grammar ✅

- [x] 建立 primitive registry、参数 schema、层级、预算、互斥、reduce-motion 和 capability fallback。
- [x] 实现首批 12 个 effect cards，并为每个 card 添加合法证据、反证和 golden recipe。
- [x] 扩展 prepared stage，使 song motif、section transform、line micro-motion 三个时间尺度独立。
- [x] 实现 Reading、Section Transform、Hero Line、Duet/Counterpoint、Aperture 五类状态。
- [x] 封面缩岛、复位、三层歌词与 Hero handoff 使用对象恒常性和确定性任意时间采样。

退出门：固定 fixture 任意 seek 得到稳定相同画面；每幕一个 primary、support 不超预算；无效果仍有完整 Reading。

## Task 4 · Performance Direction Skill 与 Director 合同 ✅

- [x] 在独立 Director 服务建立 `skills/performance-direction-v1/`，包含 SKILL、grammar、effect cards、正反例和 schema。
- [x] 扩展 full-screen contract 为 typed `EffectRecipeV1`，保留 concept/motif/intensityArc/section/directive，不降维旧字段。
- [x] Director 允许选 card、改 card 或组合已注册 primitive；新 primitive 只返回 authoring suggestion。
- [x] 服务端与客户端双重验证 evidence、primitive、参数、budget、identity 和完整 section 覆盖。
- [x] bump director/cache version；旧缓存继续回退本地计划，不错误适配成假新版本。
- [x] 后端聚焦测试覆盖合法组合、未知 primitive、低证据强效果、超预算、坏 identity 和 degraded fallback。

退出门：AI 可以做目录外的新组合，但不能输出任意代码；每个强效果有可检查的 song/section/line 证据。

## Task 5 · 生产 Runtime 集成 ✅

- [x] `StageCanvas`/后继组件直接消费完整新 plan，不经过 Legacy 三 family 降维。
- [x] Environment、Structural Field、Primary Lyrics、Memory/Counterpoint、Transition 与 Cover 共用一次 clock sample。
- [x] AI 计划仍只在下一合法 section 边界接管；当前 glyph reveal 不被 effect stagger 延后。
- [x] 性能分级先删 support/环境动态，再降静态背景，最后回完整 Reading。
- [x] pause、hidden、reduce-motion、context loss、extension reload 和 renderer replacement 均有确定恢复。

退出门：1080p 连续 240 帧 Canvas P95 ≤2ms/P99 ≤4ms；无持续 long task；GPU failure 不撤歌词。

## Task 6 · 视觉评审与真实 Chrome UAT

- [x] 固定 fixture 检查常态、Hook、转折、duet、silence、终章、长句、line-only、reduce-motion。
- [x] 完成减法视觉审计：删除大面积对称空面板、重复结构层、常驻网格/轨道/汇聚射线和满屏卡片；普通 Reading 只保留封面取色、光、材质与留白。
- [x] 真实封面在浏览器本地中心采样并生成 OKLCH 可读色板；取色失败时中性 fallback 不阻塞封面和歌词。
- [x] Director Skill v3 加入反科技模板与单一 motif owner 门；线上安静歌曲 canary 为低强度、无 effects、无 rail/grid/panel 且 `degraded=false`。
- [ ] 真实 YTM 快歌、慢歌、重复副歌、二重唱、长句各一首，完整播放并各做 20 次随机 seek。
- [x] 专门检查普通段是否安静、Hero 是否稀疏、封面是否稳定、三层歌词是否可读、效果理由是否成立。
- [ ] 与当前版本、Apple Music 参考和 AMLL baseline 做盲序截图/录屏 A/B；不展示版本标签影响判断。
- [ ] 用户完成整首主观验收后，再调模糊、缩岛比例、曲线和效果密度；不得在未看真实画面前扩大 grammar。

退出门：自动门、性能门、真实 Chrome 门与用户整首视觉门全部关闭，才更新 Release Candidate。

## 实施顺序与停止条件

```text
Task 0 baseline
  -> Task 1 shell
  -> Task 2 AMLL ADR
  -> Task 3 local grammar
  -> Task 4 Director skill
  -> Task 5 production runtime
  -> Task 6 real visual UAT
```

- 任一阶段若破坏歌词完整性、宿主时钟、随机 seek 或原生 Lyrics 恢复，停止扩展效果并先修基础门。
- AMLL spike 若导致双 renderer ownership 或不可接受的 handoff 跳变，采用单 renderer 路径，不因已经投入而继续。
- AI 视觉没有稳定优于 local plan 时，保持 local 默认，不把联网配置设为完整体验前提。
- 用户不需要继续抽象选择动画参数；只有真实 A/B 暴露明确审美分歧时才请求决定。
