# Phase 06-02 — 单窗口全屏 Stage Alpha 与 YouTube Music Companion v0

## 目标

完成第一张真正可观看的大屏舞台：本地音频 + LRC/规范歌词可在单个浏览器窗口中排练并进入全屏；随后按用户授权追加 YouTube Music 作为第一个在线来源。它必须利用整个画幅，而不是把 iPhone 中央窄列放大。

## Task 1 · 本地导入与唯一播放时钟

- [x] 建立 `web/apps/stage`，React 只管理导入、控制与资源生命周期。
- [x] 支持本地 MP3/M4A/WAV 的 Object URL，以及 LRC / canonical `LyricDocumentV0` JSON 导入。
- [x] 建立唯一 `<audio>` 与 `PlaybackClock`；rAF 每帧读取绝对 `currentTime`，不积分 delta。
- [x] seek 的恢复计时从 `seeked` 事件或媒体时间进入目标容差后开始，不从设置 `currentTime` 的瞬间开始。
- [x] 切歌、换歌词、resize 与字体变化都使用新 identity；旧 compile 结果不可回写。

## Task 2 · Local fallback 与 PreparedStage

- [x] 实现 static-first local director、语义 `PerformancePlanV0` 与 O(log n) timeline sample。
- [x] 实现页面线程上的有界 prepared typography：字体加载、`measureText`、换行、行/字几何与安全区。
- [x] 实现 Canvas 2D renderer；每帧禁止全文扫描、测字、wrap、sort、hash 与 React state 更新。
- [x] 先支持完整静态/短落点 fallback、Rail Handoff 与 Chorus Memory 两个大屏 family。
- [x] Semantic Lens 与 Silence Aperture 可以解码，但在没有相应能力/事实时降级为完整 fallback，不伪造音频依据。

## Task 3 · 单窗口排练与全屏

- [x] 同一页面提供排练控制与“进入全屏 Stage”；本期不创建第二窗口或 BroadcastChannel。
- [x] Fullscreen Stage 隐藏控制，退出后回到排练页，仍由同一个 `<audio>` 拥有声音和时钟。
- [x] 加入 Reduce Motion、字体加载、歌词非法、无逐字与音频不可播放等明确状态。
- [x] 建立由 viewport identity 驱动的 720p/1080p/1440p 与 16:10 prepared layout；超宽只延展环境/留白，不拉伸正文。

## Task 4 · YouTube Music Companion v0

- [x] 新增 Chrome/Edge Manifest V3 扩展；content script 只读取公开页面中的当前曲目展示信息与 HTMLMediaElement 播放快照，不调用 YouTube 内部接口。
- [x] Service Worker 只保留一个权威来源标签页；多 YTM 标签不会让 Stage 来回跳曲，关闭/离开来源标签会明确断连。
- [x] Stage 使用版本化 snapshot contract 与外部 `PlaybackClockV0`；播放中只在两次快照间外推，暂停不前进，新快照持续重校准。
- [x] 切歌时立即撤下旧歌词并要求导入当前录音歌词；本地音频模式保持完整可用。
- [x] Cookie、媒体 URL、音频与播放控制不离开 YouTube Music 标签页；第一版 Stage 的 seek/play/pause 只提供返回 YTM 的入口。
- [x] 原生 Lyrics 成为唯一入口，content script 在识别 `MUSIC_PAGE_TYPE_TRACK_LYRICS` 激活后挂载在原生 renderer 内部；精确隐藏与恢复原生歌词节点（display/hidden/aria-hidden/inert），不注入自定义同级标签或 sibling panel，扩展弹窗直接激活权威原生歌词标签。
- [x] 嵌入模式提供透明轻盈的侧栏 Column 与全画幅 StageCanvas（快捷键 F 进入，Esc 仅从全屏退出回侧栏）；歌词候选/搜索错误以轻量内嵌状态层出现，不另建播放时钟。

## Task 5 · YouTube Music 自动歌词

- [x] 换歌后以 `videoID + 标题 + 歌手 + 时长` 启动独立歌词请求；旧曲结果不能覆盖新曲，歌词网络不进入媒体播放链路。
- [x] 扩展后台先查 `chrome.storage.local`，再访问公开 LRCLIB `/api/get` / `/api/search`；不读取 Cookie、不上传音频、不内置服务密钥。
- [x] 只有标题/歌手匹配且时长差不超过 4 秒的同步歌词自动装入；歧义候选由用户显式选择，失败保留手动 LRC/JSON 导入。
- [x] 已确认结果缓存 30 天，候选 1 天、miss 6 小时，缓存总量有界为 100 首。
- [ ] 在重新加载后的真实 Chrome 扩展中确认《You & 合図》自动显示、换歌撤词、候选选择与缓存恢复。
- [ ] 在真实 YTM 页面确认原生 Lyrics 增强挂载，切换 Up next / Comments / Related 精确恢复原生 DOM，宽屏与窄屏均无页面级覆盖。

## 验证

- [ ] 从空页面导入音频与歌词后，不联网即可完整播放并全屏。
- [ ] pause 完全静止；20 个随机 seek 从 `seeked`/目标容差开始计，两帧内定位到正确 scene/reveal；resume 不累积漂移。
- [ ] 长句完整换行，无省略号、裁切或安全区越界；line-only 不伪逐字；双声部基础站位不互相覆盖。
- [x] 同一语义输入产生确定性的 `PerformancePlanV0`；`PreparedStageV0` 只在同 renderer/capability/font/viewport identity 内确定。
- [ ] 1080p 整个 rAF callback p95 < 8ms、p99 < 16.67ms；播放阶段无 layout/compile 导致的 >50ms main-thread long task。
- [ ] Chrome(macOS) 与 Edge(Windows) 固定时刻关键帧通过；WebKit 只做基础 smoke。
- [ ] 以“加载已解压扩展”完成一次真实 YTM 验收：连接、播放/暂停、YTM seek 后重校准、换歌撤词、多标签选择与关闭来源断连均符合合同。

## 大屏人工视觉退出门

Rail Handoff 与 Chorus Memory 各至少一张 1080p 固定关键帧必须同时满足：

- 不存在固定 340pt 窄内容列、手机卡片轮廓或播放器 chrome；
- 形成跨画幅结构关系，或明确的主/次两个空间区；
- 正文在实际桌面/投影观看距离保持可读；
- 普通正文落稳后静止，不靠持续跳动证明“有演出”。

## 完成定义

这是一张可观看的单窗口 Stage alpha，不是完整 v0。第二窗口、音频分析、Luna、演出包与断网 Show Mode 分别留给 06-03 至 06-05。
