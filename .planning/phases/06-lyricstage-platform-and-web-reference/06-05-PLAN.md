# Phase 06-05 — 第二屏 Show Mode 与 v0 验收

## 目标

把排练页与观众画面分窗，在 Mac Chrome 与 Windows Edge 的第二屏上完整演完同一首 5–6 分钟歌曲。

## Task 1 · 唯一音频所有权与分窗协议

- [ ] `/stage` 窗独占唯一 `<audio>` 与声音输出；Control 不创建第二播放时钟。
- [ ] 进入 Show Mode 前停止 Control 预览，将资源/初始状态交给 Stage。
- [ ] `/control` 只通过 BroadcastChannel 发送 command、接收 Stage snapshot；Stage 每帧直接读本窗 `currentTime`。
- [ ] 定义 load/ready/play/pause/seek/restart/blackout/close/error snapshot 与 generation identity。

## Task 2 · 观众与控制表面

- [ ] Control 只保留载入、预览、开始、暂停、seek、restart、blackout 与退出。
- [ ] Stage 全屏后无按钮、toast、debug label、错误栈或鼠标残留。
- [ ] Stage 关闭、断连、退出全屏时安全静止或 blackout；重新打开可恢复当前媒体时刻。
- [ ] 正式演出只读已完成 preflight 的本地资源，不发网络请求。

## Task 3 · 双机真实验收

- [ ] Mac Chrome 外接屏/显示器完整演一首 5–6 分钟真实歌曲。
- [ ] Windows Edge 第二屏用同一 `.lyricstage` 包与对应本地音频再演一次。
- [ ] 两次各做 20 个随机 seek、pause/resume、restart 与一次 Stage 重连。
- [ ] 记录 rAF、掉帧、long task、内存平台与故障恢复；不把 Canvas 子区间冒充整帧性能。

## 验证

- [ ] 两台机器的正文、时间、声部、scene 与结构语义一致；字体栅格差异不算失败。
- [ ] 5–6 分钟内无明显卡顿、连续 missed frame 或稳定后持续内存增长。
- [ ] `seeked`/目标容差后两帧内恢复当前 scene；暂停完全冻结。
- [ ] 断网、关闭 Stage、退出全屏和重开都回到安全状态，不损坏用户音频或演出包。

## Phase 06 完成定义

```text
本地音频 + 时间轴歌词
  -> local fallback / 可选 Luna Recipe
  -> 排练与演出包
  -> 第二屏 1080p 全屏
  -> 断网连续演完
  -> seek / pause / restart / reconnect 确定性恢复
```

到这里才启动完整 Bilibili Provider；已经存在的 YouTube Music Companion 只作为播放桥接参与验收，不扩张成在线曲库客户端。
