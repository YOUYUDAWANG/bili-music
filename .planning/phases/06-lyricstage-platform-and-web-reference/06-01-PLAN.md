# Phase 06-01 — 正式重基线、合同与 Golden Fixtures

## 目标

把已提交的 iOS V4 参考实现转成来源无关、可由 Swift 与 TypeScript 共同验证的线协议；不实现 Web 渲染器，不改 iOS 默认播放路径。

## Task 1 · 用户确认后正式重基线

- [x] 以明确提交作为 iOS V3/V4 reference checkpoint。
- [x] 更新 `.planning/PROJECT.md`：BiliMusic 是第一个客户端，LyricStage 是仓库内孵化的平台内核。
- [x] 修正 `.planning/STATE.md` 的 Phase 4/5/100% 冲突，并激活 Phase 06。
- [x] 在 `.planning/ROADMAP.md` 补记 Phase 05 历史并加入 Phase 06 的 01–05 计划。
- [x] 在 `.planning/REQUIREMENTS.md` 新增 CORE/WEB/SHOW 需求；保留 iOS backlog，但不再把 Web Stage 列为全局 out-of-scope。

## Task 2 · 建立独立 Web 合同 workspace

- [x] 新建 `web/` npm workspace、TypeScript strict、Vitest 与 `packages/contracts`。
- [ ] 以 JSON Schema 2020-12 定义：
  - `RecordingIdentityV0` / `ProviderTrackRefV0`；
  - `LyricDocumentV0`；
  - `AudioStructureFactsV0`；
  - `DirectorRecipeV0`；
  - `.lyricstage` manifest。
- [x] 生成或手写严格 TS 类型与 Ajv validator；schema 是唯一线协议真相。
- [x] `recordingID` 只做包内 opaque ID，`assetHash` 只做本地失效；本期不解决跨 Provider 同录音自动识别。

## Task 3 · 建立无版权 Golden Corpus

- [x] 从现有 Swift V4 测试提炼不含真实歌词正文/音频的共享 fixture。
- [x] 覆盖：逐行日文、中英日混排逐字、超长行、重复 Hook、二重唱/和声、5–6 分钟长歌结构。
- [x] 为 Swift 添加最小 conformance test，读取同一 fixture 并验证正文、时间、声部与版本。
- [x] 明确跨语言只比较语义合同、canonical JSON/hash 与 identity；不比较字体几何、prepared layout 或像素输出。

## 验证

- [x] TS schema 正反例与 canonical hash 测试通过。
- [x] Swift 与 TS 对同一 fixture 得到相同正文、时间与声部；canonical identity 的跨语言字节对照仍待 AudioStructure 合同一起补齐。
- [x] `providerRefs` 为空时合同仍成立；bvid/cid 不再是核心必填项。
- [x] 无逐字 fixture 不出现真实 word timing；任何输入都不静默截正文。
- [ ] 未知 recipe scene 可以局部丢弃，不破坏 lyric document。
- [x] 未修改 iOS App、Worker 与线上服务；`git diff --check` 通过。
