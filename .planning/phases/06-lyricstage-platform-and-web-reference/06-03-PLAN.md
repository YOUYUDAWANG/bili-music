# Phase 06-03 — Web 音频结构与完整大屏语法

## 目标

让大屏演出真正消费本地音频事实，并完成 Semantic Lens、Silence Aperture 与四种 family 的全屏编译；仍不调用 Luna。

## Task 1 · 可取消的音频分析数据通路

- [ ] 页面用 `decodeAudioData` 异步解码；`AudioBuffer` 不直接 transfer。
- [ ] 以有界分片在页面线程 downmix/resample 为 mono `Float32Array`，随后 transfer ownership 给 Web Worker。
- [ ] Worker 执行 hash、energy/onset/tempo/silence/section 分析并输出兼容 `AudioPerformanceMapV2` 的版本化结果。
- [ ] 完成/取消后释放 PCM；分析未完成或失败时继续使用完整 fallback。
- [ ] PCM 转换和分片本身不得在播放中制造 >50ms main-thread long task。

## Task 2 · AudioStructure 与完整四 family

- [ ] 从 map 生成兼容 `AudioStructureScoreV4` 的结构事实。
- [ ] Rail Handoff、Semantic Lens、Chorus Memory、Silence Aperture 全部按 `fullscreen16x9` 重新编译。
- [ ] lyric clock 与 raw audio clock 分离；音频只驱动 section、环境、结构线与 reveal 后 accent。
- [ ] 增加 TTML/YRC/QRC 等真实逐字导入适配；不做浏览器 ASR 或平均伪逐字。
- [ ] 用 golden recipes 驱动视觉测试；普通 LRC 在音频事实准备前继续走 lyric-only fallback。

## Task 3 · 可选 WebGL2 环境层

- [ ] 先测 Canvas 2D 是否足够；只有环境层确有需要才启用 WebGL2。
- [ ] Canvas 文字与 WebGL 环境共用一个 rAF、一个媒体时间样本、固定 DPR/分辨率和明确叠层顺序。
- [ ] `webglcontextlost` 时即时降级到静态 Canvas 完整歌词。
- [ ] 性能同时记录 text draw、整个 rAF callback、掉帧率与连续 missed frame，不允许 Canvas 单项吃完整帧预算后再叠 GPU 效果。

## 验证

- [ ] 音频分析不阻塞首次出声，失败仍可整首演完。
- [ ] 用户 lyric offset 不移动真实 beat/onset/section；真实逐字 reveal 不等待音频事件。
- [ ] 四个 family 各有 1080p 大屏关键帧并通过无窄列/跨画幅/可读性门禁。
- [ ] 同 map/lyrics/recipe/capability 得到相同语义 plan；字体几何只在本 renderer identity 内确定。
- [ ] 启用环境层后整个 rAF p95 < 8ms、p99 < 16.67ms，无连续超预算；context loss fallback 可用。

## 完成定义

不用模型，Web 已能从本地音频事实与歌词确定性生成完整四 family 的全屏演出。
