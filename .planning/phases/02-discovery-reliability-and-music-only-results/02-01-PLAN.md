# Phase 2 Plan: Discovery Reliability and Music-Only Results

## Phase Goal

Users can search, paginate, and use Home or Now Playing recommendations without stale results, refresh collisions, or non-music content polluting the default music surfaces.

## Work Completed

1. Search requests now carry query, mode, and request identity through first-page and pagination flows. Stale results from older work are rejected before they mutate visible state.
2. Search pagination now preserves existing results when a later page fails, exposes a retry message, rebuilds sections after appending, and keeps every page under the same music-only filtering rules.
3. Now Playing recommendation taps no longer immediately clear or refresh the visible related list. Hidden recommendation panels are marked stale and refresh when reopened; visible external track changes still refresh immediately.
4. Recommendation candidate pools now apply displayable music filtering before scoring and before the final visible pool is shown.
