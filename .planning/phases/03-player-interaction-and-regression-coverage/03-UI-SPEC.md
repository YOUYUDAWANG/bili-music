| Property | Value |
|----------|-------|
| Tool | none - native SwiftUI and existing `AppTheme` |
| Preset | not applicable |
| Component library | SwiftUI native components plus app-local player views |
| Icon library | SF Symbols only |

**Source:** `.planning/PROJECT.md`, `.planning/REQUIREMENTS.md`, `.planning/phases/03-player-interaction-and-regression-coverage/03-CONTEXT.md`, `.planning/codebase/STACK.md`, `BiliMusic/Design/AppTheme.swift`.

**Design direction:** Use a conservative Apple Music-like native iOS player. Do not adopt a web entertainment design system, external fonts, heavy green/dark palettes, large marketing layouts, or decorative web effects. The only intentional brand accent is the existing Apple Music-like red from `AppTheme.accent`; the rest of the interface uses system semantic colors and album-art-derived player atmosphere where already supported.

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4pt | Icon gaps, compact metadata gaps, progress time spacing |
| sm | 8pt | Compact control spacing, row internals, page-dot gaps |
| md | 16pt | Default player padding, top chrome padding, toolbar padding |
| lg | 24pt | Page horizontal padding, sheet/list vertical rhythm |
| xl | 32pt | Cover-to-metadata and controls-to-toolbar spacing on tall screens |
| 2xl | 48pt | Major center-page vertical grouping on tall iPhones |
| 3xl | 64pt | Maximum page-level breathing room only when vertical space allows |

Exceptions:

- Icon-only hit targets are minimum 44pt by 44pt; primary playback buttons use the existing 56pt control frame.
- Progress scrub target stays 44pt high while the visual track remains 3pt.
- Mini progress stroke may remain 1.5pt because it is a stroke, not spacing.
- Existing app radii remain: `AppTheme.coverRadius` 6pt, `AppTheme.controlRadius` 12pt, `AppTheme.cardRadius` 12pt, `AppTheme.playerCoverRadius` 14pt.
- Cover art uses responsive sizing, not a fixed spacing token: center page cover should fit between 260pt and 420pt where possible and avoid creating a large bottom void.
- Gesture thresholds are interaction policy constants, not layout spacing. Keep them in `PlayerGesturePolicy`.

## Typography

Use exactly these four base text roles for the player phase. Dynamic Type may scale them, but visual hierarchy must remain the same. Use only two weights: regular 400 and semibold 600.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 17pt | regular 400 | 1.5 |
| Label | 13pt | regular 400 | 1.3 |
| Heading | 22pt | semibold 600 | 1.2 |
| Display | 28pt | semibold 600 | 1.15 |

Usage:

- Display: current track title on the center Now Playing page, capped to two lines with fade/truncation that does not push controls offscreen.
- Heading: queue/recommendation page title, sheet title, and prominent empty-state heading.
- Body: owner/UP metadata, list titles when not promoted, error bodies.
- Label: progress time, toolbar labels where visible, secondary metadata, page hints.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `AppTheme.background` / `.systemBackground` | Main player surfaces, sheet backgrounds, center Now Playing body |
| Secondary (30%) | `AppTheme.groupedBackground` and `AppTheme.secondaryBackground` | Queue/recommendation list panels, toolbar backing, empty/loading/error regions |
| Accent (10%) | `AppTheme.accent` / `.systemRed` | Active player toolbar states, selected page indicator, current queue/recommendation emphasis only |
| Destructive | `AppTheme.error` / `.red` | Destructive actions only; Phase 3 adds no new destructive player action |

Accent reserved for: active lyrics state, active favorite state, cached/downloaded state, selected audio quality affordance, active MV/music toggle state, selected lightweight page hint, and the currently playing item marker in queue/recommendations. Do not use accent as the default color for all tappable controls; inactive controls use primary or secondary semantic foreground.

Disabled state: disabled/inactive controls use `.secondary` or `.tertiary` foreground with stable alignment and at least 44pt hit area when visible. Lyrics unavailable must remain aligned in the toolbar and appear inactive, not disappear.

Contrast: all readable text must satisfy iOS semantic-color contrast in light and dark mode. Do not encode state by color alone; pair state with icon shape, opacity, label, or accessibility value.

## Player Layout Contract

**Full-player model:** The full player has exactly three horizontal pages: left queue, center Now Playing, right recommendations. Opening the player lands on the center page every time unless a later explicit user action changes the page while the full player remains open.

**Center Now Playing page:** Use a dense Apple Music-like vertical composition:

1. Top chrome with grabber/close affordance and lightweight page hint.
2. Large cover art as the dominant object.
3. Track title and UP/owner metadata.
4. Progress scrubber with current and duration labels.
5. Large playback controls.
6. Unified secondary toolbar with lyrics, favorite, cache/download, audio quality, and MV switch.

The center page must not stack multiple card-like panels under playback controls. The bottom third must not collapse into empty space on supported iPhone sizes.

**Queue page:** Left page shows current playback queue in a scrollable list. The current track is visually marked. Empty/loading/error states are stable, centered in the page body, and do not dismiss the player.

**Recommendation page:** Right page shows current-song recommendations from the existing recommendation state. Tapping a recommendation starts playback without immediately clearing, scrambling, or refreshing the visible list.

**Page hints:** Use small page dots or a thin indicator plus fading page title. Do not use a heavy segmented control. Page hints must be readable but visually secondary to playback.

**Toolbar contract:** Persistent actions, left to right unless implementation has a stronger native ordering:

| Action | Icon Guidance | State Contract |
|--------|---------------|----------------|
| Lyrics | SF Symbol lyrics/text icon | Enabled when lyrics exist; disabled but aligned when unavailable |
| Favorite | heart / heart.fill | Active state uses accent and accessible selected state |
| Cache/download | arrow.down.circle / checkmark.circle | Loading/downloading shows progress or busy state without layout shift |
| Audio quality | hifispeaker / waveform / quality text fallback | Opens existing quality action or sheet; selected state is visible |
| MV switch | music.note and play.rectangle style toggle | Preserves existing music/MV behavior while matching toolbar styling |

Playback mode may sit near primary playback controls or in a secondary menu. It must not displace the five persistent toolbar actions.

## Interaction Contract

**Mini-player expansion:**

- Upward drag on the mini-player directly drives full-player offset from the bottom.
- The full player opacity and scale track drag progress continuously.
- The mini-player fades and scales away as the full player emerges.
- Release completes or cancels using `PlayerGesturePolicy` distance and velocity thresholds.
- Tap-to-open remains available as a fallback.

**Full-player minimization:**

- Center page can minimize from top chrome, cover area, player body, and blank areas.
- Queue and recommendation pages can minimize only from top chrome/grabber/title area.
- Scrolling inside queue or recommendation lists must never dismiss the player.
- Downward dismiss requires a deliberate vertical gesture; horizontal swipes and progress scrubs must not satisfy dismissal.

**Gesture conflict rules:**

- Progress scrub uses a high-priority local drag target and suppresses horizontal page swipe while active.
- Horizontal page swipe changes queue/Now Playing/recommendation pages only when the drag is primarily horizontal.
- Vertical dismiss only tracks primarily downward vertical drags in allowed regions.
- List scroll owns vertical movement inside queue and recommendation list bodies.

**Motion:**

- Use state-driven SwiftUI transitions via `withAnimation` or `.animation`.
- Respect `@Environment(\.accessibilityReduceMotion)`.
- Standard animation: 180-260 ms ease-out/ease-in-out for page hints, toolbar state, and player open/close settle.
- Reduced Motion: remove scale-heavy and springy movement; use short opacity/offset transitions that still communicate hierarchy.
- Avoid expensive blur, particle effects, complex physics, or constantly animating backgrounds. Playback startup and stable audio outrank visual polish.

## Accessibility And Responsive Contract

- All toolbar and playback controls have explicit accessibility labels in Chinese.
- Disabled toolbar controls remain discoverable through accessibility with an unavailable state or clear label.
- Hit targets are at least 44pt by 44pt.
- Progress time uses monospaced digits.
- Text must not overlap cover art, progress controls, or toolbar on compact iPhone heights.
- Long titles truncate or fade after two lines; owner metadata truncates to one line.
- Test visual layout on compact and modern iPhone sizes, including 375pt-wide class and iPhone 16 simulator.
- Honor safe area top and bottom insets for full-player overlay, mini-player accessory, and toolbar.
