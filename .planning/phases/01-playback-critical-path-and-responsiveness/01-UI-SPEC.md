# Phase 01 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

## Design System

| Property | Value |
|----------|-------|
| Tool | Native SwiftUI manual design system. Source: `BiliMusic/Design/AppTheme.swift`, `TrackRow.swift`, `UIComponents.swift`. |
| Preset | Not applicable. This is a SwiftUI iOS app, not React/Next/Vite; no shadcn initialization for Phase 1. |
| Component library | SwiftUI system controls plus local BiliMusic design primitives: `TrackRow`, `CachedAsyncImage`, `MiniProgressBar`, `ContentUnavailableView`, `List(.insetGrouped)`. |

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4pt | Track metadata stack gaps, compact inline icon/text gaps, tight progress/control spacing. Source: existing row spacing. |
| sm | 8pt | Default control-group gap, mini-player control gap, compact vertical row rhythm. Default. |
| md | 16pt | Screen edge padding, player top/content insets, section-to-section rhythm. Source: `NowPlayingView.Layout`. |
| lg | 24pt | Empty-state vertical insets, list unavailable-row top/bottom insets, major state separation. Source: `SearchView.unavailableRow`. |
| xl | 32pt | Full-player control cluster separation only when already present; do not add new empty vertical void in Phase 1. Default. |
| 2xl | 48pt | Major modal/player vertical transition spacing only; avoid on search/home list content. Default. |
| 3xl | 64pt | Reserved for full-player cover/list page structure; Phase 1 should not introduce new 64pt gaps. Default. |

Exceptions: iOS touch targets must remain at least 44pt for tappable row menus and player controls. Existing fixed media sizes are allowed: `TrackRow` thumbnail 64x36pt, mini-player artwork 34x19pt to 44x25pt, mini-player height 40-48pt. These are component dimensions, not layout spacing.

## Typography

Use exactly these four size roles and exactly two weights, regular 400 and semibold 600. Prefer SwiftUI semantic styles that map to these roles so Dynamic Type remains available.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 15pt | 400 | 1.45 |
| Label | 12pt | 400 | 1.30 |
| Heading | 20pt | 600 | 1.20 |
| Display | 28pt | 600 | 1.15 |

Contract: Phase 1 list rows use Body for titles and Label for artist/duration/status text. Semibold is reserved for navigation/player headings, selected/current track emphasis, and action buttons. Display is allowed only where the existing full-player surface already uses large track text; do not add hero-scale copy to Home or Search.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `UIColor.systemGroupedBackground` dynamic color, light `#F2F2F7`, dark `#000000`. Source: `AppTheme.groupedBackground`. | Root Home/Search list backgrounds and performance-safe empty surfaces. |
| Secondary (30%) | `UIColor.secondarySystemGroupedBackground` dynamic color, light `#FFFFFF`, dark `#1C1C1E`. Source: `AppTheme.secondaryBackground`. | Row/card/list item surfaces, thumbnail placeholders, grouped list cells. |
| Accent (10%) | `UIColor.systemRed` dynamic color, light `#FF3B30`, dark `#FF453A`. Source: `AppTheme.accent`. | Current-track title tint, playing waveform/speaker icon, active playback/progress state, selected player mode only. |
| Destructive | `Color.red` / system destructive role. Source: `AppTheme.error` and SwiftUI `.destructive`. | Destructive actions and error text only. |

Accent reserved for: currently playing row title, waveform/speaker indicators, playback progress state, active music/MV/player mode, and explicit selected playback affordances. Do not use accent for every tappable row, neutral placeholder, loading spinner, or Home recommendation refresh state.

## Phase 1 Interaction Contracts

### Search Focus

Focusing the empty search field must render local content only: recent playback, cached songs where available, and up to 8 local search-history suggestions. Focus, keyboard presentation, and normal typing must not show network loading copy, trigger Bilibili search, prewarm WBI, or decode image-heavy result content. Source: `SRCH-01`, `SRCH-02`, `D-05` through `D-07`.

Search empty state must remain lightweight: use `ContentUnavailableView("搜索音乐", systemImage: "magnifyingglass", description: Text("输入歌名或 UP 主查找音乐内容"))` when no local suggestions exist. Minimum empty-row height is 220pt with 24pt vertical insets, matching the existing `SearchView` contract.

### Home Recommendation Stability

Starting the first song after app launch must not visually clear, flash, replace, or auto-refresh the visible Home recommendation list. If recommendations become stale as a side effect of playback, mark them internally only. The visible list remains stable until the user pulls to refresh or taps `换一批`. Source: `RECO-01`, `RECO-04`, `D-08` through `D-10`.

When Home has no recommendations, use the fixed Home empty copy above. When Home has existing recommendations and a refresh fails, keep the existing rows visible and show error text without replacing the list with a blank state.

### Image-Heavy Surfaces

Search, Home, mini-player, and player preview surfaces must prefer responsiveness over immediate image completeness. Use neutral placeholders from `AppTheme.secondaryBackground` or low-opacity primary placeholders; do not block row rendering on cover art. Source: `MEM-01` through `MEM-03`, `D-11` through `D-13`.

List thumbnails should keep stable dimensions so late image arrival does not shift rows: 64x36pt for `TrackRow`, 34x19pt to 44x25pt for mini-player artwork, and existing full-player cover sizing only. Image loading may appear late, but text, row hit targets, and playback controls must remain interactive.

### Playback and Mini-Player Responsiveness

Track taps must show immediate current-track feedback before lyrics, recommendations, MV probing, artwork, auto-cache, or history flush finishes. Current-track feedback is the existing row title accent plus waveform/speaker indicator. Source: `PLAY-01`, `PLAY-05`, `D-01` through `D-04`.

The mini-player must remain visually dense and single-hand friendly: 40-48pt height, one-line title, one-line artist, 28-32pt icon button frames, and no new blocking loading state for post-start enrichment. Loading indicators belong on search/recommendation rows, not over playback controls.

### Out-of-Scope Guardrail

Do not use Phase 1 to redesign the full Now Playing page, queue/recommendation pages, player drag dismissal zones, favorite-folder selection, MV fullscreen polish, auth-expired routing, cache quota/delete UX, or broad Apple Music visual polish. Those are Phase 2/3 or v2 items unless a narrow visual state is required to protect Phase 1 playback, search focus, Home stability, or image memory behavior.
