## Phase Goal

**As a** user, **I want to** tapping a track, focusing search, and scrolling image-heavy music surfaces to stay responsive, **so that** the app reliably gets to music before background enrichment or recommendation work can interfere.

<objective>
Protect the first playback slice from tap to AVPlayer play request.

Purpose: PLAY-01, PLAY-02, PLAY-04, PLAY-05, D-01, D-02, D-03, and D-08 require first sound to win over enrichment and prepared-stream failure cases.
Output: A source-kind-aware playback start path, one prepared-stream retry, diagnostics for the protected path, and unit tests proving enrichment is not awaited before playback.
</objective>

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-03 | Information Disclosure | `PlayerEngine` diagnostics | mitigate | Reuse sanitized diagnostic events; never emit request headers, auth material, or full remote media URLs. |
| T-01-04 | Tampering/DoS | prepared stream retry | mitigate | Keep prepared remote URLs memory-only, invalidate stale entries, retry once, and surface failure instead of looping. |
| T-01-05 | Denial of Service | post-start enrichment | mitigate | Move history/artwork/lyrics/MV/prefetch/auto-cache behind post-start scheduling with generation guards so enrichment cannot block first playback. |
| T-01-SC | Tampering | package installs | accept | No package-manager install is planned. |
</threat_model>
