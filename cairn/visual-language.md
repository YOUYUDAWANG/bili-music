# BiliMusic 视觉语言

**状态：** 2026-08-14 已落地首版，待真机日常使用确认。

## 当前结论

BiliMusic 不再把 Apple Music 当作完整视觉模板。Apple Music 只提供成熟的 iOS 交互模型；内容层使用 B 站 16:9 封面形成“横版影像唱片机”。

| 层级 | 当前语言 |
|---|---|
| 系统外壳 | 原生 `TabView` + LNPopup mini/full 开合；有歌曲时按 `.onScrollDown` 共同进入 iOS 27 inline 紧凑态，不自绘底栏 |
| 首页 | 纯粹的纵向海报瀑布流；1 张全宽 + 4 张双列连续重复 |
| 播放器 | 16:9 封面接近屏幕边缘；标题/歌手沿封面左缘排版；封面派生双色光场 |
| 工具页 | 搜索、缓存、设置与普通列表保持高效率和克制蓝青强调色 |

## 用户需求摘要与优先级

1. **真实封面是主角。** 不用高饱和生成撞色、封面模糊背景或装饰模板压过 B 站原图。
2. **首页保持纯粹瀑布流。** 固定“1 张全宽 + 4 张双列”纵向重复，不加入横向胶片、多模板或按下载分辨率动态重排。
3. **密度高但不能廉价。** 使用 8pt 页面边距、4pt 组内、8pt 组间、4pt 圆角；顶部允许封面穿透，但按钮必须保持独立可读。
4. **兼容系统 Liquid Glass。** 玻璃负责 Tab、mini player 和必要控制外壳，不包裹内容画布；工具页继续效率优先。
5. **封面选择与播放器状态必须连续。** 点击哪张封面就立即提交哪首歌，并由同一个 LNPopup 播放器展开；不再要求封面从原位几何放大。统一生命周期、跟手开合和稳定滚动优先于跨层视觉连续性。
6. **视觉目标不能透支稳定性。** 不以四个 Tab 常驻、自绘底栏、同步伪播放状态或全屏手势竞争换取动画；播放启动、滚动和队列/进度手势优先保持稳定。

## 首页规则

- 只使用真实封面，保持 16:9，不在选择面叠标题。
- 按原始顺序切成每组 5 张：1 张全宽、其后 4 张双列；只沿纵向滚动，不插入横向胶片带或其他版式。
- 页面左右边距为 8pt；同一 1+4 组内部使用 4pt 间距，组与组之间使用 8pt 间距，卡片使用 4pt continuous 圆角。`8 / 4 / 8` 构成稳定的 1:2 基础节奏，不再用统一极窄接缝填满画面。
- 沟槽与页面固定使用 `AppTheme.background`；不从封面派生首页环境色，也不对全宽或双列封面做滚动视差，避免彩色漏缝和文字型封面裁切晃动。
- 当前播放态只在封面底部显示一条 3pt 真实进度线：黑色底轨 0.65、白色播放填充 0.95；不叠加渐变、整卡描边、waveform 角标或持续装饰动画。
- 收藏夹接口不提供原图宽高；当前缩略图请求会统一裁成 `width × width*9/16`，因此不能用下载后的分辨率反推排版。若未来引入原始宽高，必须在首屏布局前持久化，不能让图片加载完成后跳动重排。
- 顶部 shuffle/settings 采用右上角浮动的 34pt 高度 Liquid Glass / UltraThinMaterial 胶囊，两项操作各自保留 42×34pt（有效热区 >=44pt）点击区域；页面顶部叠加 72pt 暗色柔和渐变光晕（0.65 -> clear）保护状态栏与胶囊对比度，海报瀑布流向上自然穿透。
- 第一张封面在静止状态距顶部胶囊保留呼吸空间；底部依赖原生 Tab Bar 与 LNPopup 的动态安全区，并额外保留 8pt resting buffer，不自绘底部暗光或浮岛。
- 交互流：首页点击海报由 `PlayerEngine.beginPlayback` 同一帧提交唯一真实选曲，再请求 RootView 打开现有 LNPopup；关闭后回到同一 ScrollView 和标准 mini player。Home 不挂载播放器副本、不运行 matched geometry 或延时恢复任务；其他 Tab 不常驻，底栏不自绘，播放页不叠加全屏关闭手势。

## 播放器规则

- 播放器封面是唯一 LNPopup transition target；大图使用 8pt continuous 圆角（与首页 4pt 形成自然的宽幅阶梯）。
- 背景取 `PlayerArtworkPalette.top` 与 `bottom`，只加轻微暗化；不用封面模糊、径向 glow、持续 glitch 或扫描线。
- 竖屏纵向层级固定为 `Artwork + Metadata`、`Inline Lyrics`、`Playback Cluster`、`Utility`：封面到信息为 12/16pt；中间唯一弹性区由歌词导演决定每个时间点显示 1–3 行真实时间轴文本，不固定两句；进度到主控为 12/18pt；主控到底部功能栏只留 12/18pt 有界间距。播放器与队列不显示软件音量条，音量交给实体键，AirPlay 系统入口保留。
- 中央歌词只使用真实同步时间：`LyricMotionDirector` 与 Luna v3 可在 Rise / Impact / Drift / Breathe / Echo / Focus / Drop / Stretch / Cascade 九种效果中选型。Focus 是模糊与字距收焦，Drop 从上方落定，Stretch 从横向压缩展开，Cascade 逐级带入多行且禁止用于单行；新增效果在 0.62–0.82 秒内落稳，不做持续 glitch。compositions 仍只选择当前附近真实歌词；长句保持 24–32pt 主视觉并完整换行，所有正文和 Echo 残影都禁止省略号。
- 稳定歌曲/行哈希只用于中性句的变体与方向，同一句跨启动必须一致；无逐字时间轴时绝不平均分配字符时间。动画只在 full player 展开、播放中且 App active 时运行，Reduce Motion 降级为淡入淡出；无歌词或 MV 模式保持留白，点击画布进入完整歌词。
- 播放器视觉与性能只针对用户自用的 iPhone 17 Pro / iOS 27 验收；不再用 SE 的高度和密度约束字体、位移或留白。仍保留基本自适应，避免其他尺寸直接崩坏。
- 控制区仍使用熟悉的音乐操作模型；歌词是同一层正在播放的模式切换（不是新页、不是 sheet），底部歌词按钮保持可见并再点关闭；进度/播放键/音量在歌词模式直接不出现；校准/翻译/搜索收进 `⋯` 菜单。
- MV 可保留必要系统材质浮层，普通内容和队列不新增玻璃卡。

## 已否决方向

高饱和“私人频道/播出系统”首版在模拟器实图中压过了真实封面，并与系统 Liquid Glass 形成两套竞争语言；用户明确选择撤回。随后尝试的 cinematic / film strip / offset masonry 多模板首页又打断了连续浏览节奏，也已撤回。临时 App Icon 不是视觉 DNA，不应反向约束 UI。

## 验证边界

- iPhone 17 Pro / iOS 27 Simulator 构建与窄 UI 回归必须通过；最终动效性能只以同型号 Release 真机为准。
- 用真实极端封面检查纯瀑布流和播放器长标题；缺图/加载仍保持现有中性状态。
- 检查 4pt 组内 / 8pt 组间节奏在真实封面上仍保持连续，首页播放进度订阅只局限在当前封面的细线子视图。
- LNPopup 连续开合、慢拖取消、进度 scrub、独立队列与空 mini 槽位继续由现有交互边界保护。
- 真机最终确认关注：封面密度、长时间浏览疲劳、Liquid Glass 外壳与封面墙的协调，以及动态色在音乐/MV 两态的稳定性。
